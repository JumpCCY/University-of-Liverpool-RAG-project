READ THIS FIRST - A RETRIEVAL GAP SHAPES EVERY ANSWER BELOW
==============================================================================

All six questions ask 'Liverpool vs <rival>'. The vector store behind the
'general' branch holds ONE collection, 'my_collection': 519 chunks, every one
tagged 'University of Liverpool'. It contains no rival chunks at all.

Consequence: on all six questions, all three versions retrieved Liverpool-only
context. No version could make a real comparison, however capable it is. The
rival half of every answer below is a statement about our knowledge base, not
about the rival university.

This is a data-pipeline gap, not a model defect:
  - Rival course pages ARE scraped and on disk: data/<rival>/course/*.html,
    40-208 KB each for sheffield, leeds, manchester, york, lancaster, newcastle.
  - py/embeddings/populate_vector_db.py ALREADY contains the loop that builds a
    separate Chroma collection per rival via script/rival_chunking.py (lines
    ~237-265). Those collections do not exist in the current chroma_db, so that
    loop has not been run against it.
  - Rival JSON holds only qualifications.json (entry requirements). That feeds
    the 'requirement' branch, which none of these six questions route to - all
    six are course-content / employability / student-life questions.

So the honest reading of this benchmark:
  VALID   - latency, answer format, instruction following, and how well each
            model handles a half-empty context. That last one turns out to be a
            sharp discriminator, so the exercise is still informative.
  INVALID - comparison accuracy about rivals. No version had rival facts.

Re-running populate_vector_db.py to build the rival collections would make this
same 6-question set a genuine test of comparison quality. Worth doing before
drawing conclusions about which model compares universities best.

FINDING - V2's cost is not just a bigger answering model.
V1 and V2 use the IDENTICAL qwen3.5:9b for all three routing/rewrite calls, yet
those calls cost 2.8s each in V1 and 5.7s each in V2 - a 2x inflation on work
that is byte-for-byte the same. Cause: qwen3.6:27b needs ~18 GB and qwen3.5:9b
~6.6 GB on a 24 GB machine, so they cannot stay co-resident. Ollama evicts and
reloads a model on nearly every call boundary. 'ollama ps' during the V2 run
showed qwen3.6:27b at 13%/87% CPU/GPU - i.e. spilling off the GPU as well.
V2 therefore pays a swap penalty on top of slower generation, and roughly 17s
per question is lost to routing that V1 does in 8.5s.

Practical read: on this hardware the 9b/27b split is the worst of both worlds.
Either keep everything on 9b (V1) or, if the 27b answerer is wanted, route with
it too so only one model is ever resident - or move to a machine where both fit.

3.1 ANSWER SHAPE - the clearest separator

The prompt defines three opening shapes and is explicit that a WH-question
('what are the main differences...', 'which university gives me more...') must
NOT open with a Yes/No verdict: 'NEVER open with "Yes" - it answers a question
nobody asked.' Five of the six questions are WH/choice questions; Q4 alone is
compound and may legitimately lead with a verdict.

Q    question shape          V1        V2        V3
------------------------------------------------------------------------------
Q1   WH                 VERDICT        ok        ok
Q2   WH/choice          VERDICT        ok        ok
Q3   WH                 VERDICT        ok        ok
Q4   compound           VERDICT        ok        ok
Q5   WH                 VERDICT        ok        ok
Q6   WH/choice          VERDICT        ok        ok

V1 opened EVERY answer with a bold '**Yes**' or '**No**', including all five
WH-questions - a shape violation on 5 of 6. Worse, the verdict answers the wrong
question: for 'What are the main differences between the two courses?' V1 replies
'**No** - we do not hold any information about the University of Manchester',
turning a request for differences into a negative answer about coverage. A staff
member reading that aloud mid-call leads with 'No', which sounds like Liverpool
lacks something. V2 and V3 never did this: both open with the finding.

3.2 UNSUPPORTED COMPARATIVE CLAIMS

The prompt says: 'REPORT THE DIFFERENCE, DO NOT RATE IT', and for 'which is
better for me' questions, do not pick a winner.

  V2, Q6 opens: 'Liverpool offers more flexibility for choosing optional modules
  later in the degree, as we hold detailed module lists and pathway structures
  for it, while we hold no information about University of York's course
  structure.'

That is a ranked verdict justified by our own missing data - it converts absence
of evidence about York into a win for Liverpool. It also contradicts the prompt's
rule that 'HOW MUCH WE HOLD IS NOT HOW GOOD A UNIVERSITY IS'. V3 on the same
question: 'The records document Liverpool's optional-module flexibility, but hold
no equivalent information for York, so we cannot establish which university
offers more.' That is the correct handling.

Note this slip is invisible to a keyword check - 'more flexibility' is not on the
prompt's banned-word list (stronger/better/weaker/superior/...). No version
tripped the literal banned words; V2's Q6 is a semantic violation only.

3.3 GROUNDING / HALLUCINATION - all three passed

The strictest rule in the prompt is never to name anything absent from the
retrieved text. With a Liverpool-only corpus, any concrete rival fact would be
fabricated. Every rival-mentioning line in all 18 answers was inspected:

  V1: 0 invented rival facts     V2: 0 invented rival facts     V3: 0 invented

All three consistently said the information is not held rather than guessing -
including on Q3 (Leeds employability) and Q5 (Lancaster student life), where a
model drawing on general world knowledge would find it easy to improvise. This
is the pipeline's strongest result and it holds at every model size.
